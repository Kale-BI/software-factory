Evidence and dossiers

A tracker where agents do most of the writing drowns in report-dumps unless legibility is engineered. Ours is engineered around three ideas: the glance, the long-form home, and evidence named in advance.

The glance

Every note an agent leaves on a ticket is written to be read in one breath, the way an engineer reports to their CEO: "this is done", "blocked on X, diagnosis attached", "filed Y as a new issue". Detail lives in the linked artifact and never in the comment itself. An unattended run additionally opens with a fixed marker — "Generated by AI during triage." — so a reader always knows which voice is speaking.

The test a comment must pass: a colleague who was not in the session reads it once and knows what happened and what, if anything, they owe. A wall of text fails even when every sentence in it is true.

The long-form home

Long-form records — grilling records, plans, accumulated evidence — do not go in comments. Each effort has one accreting long-form page at the team's internal, access-walled dossier site; every resolved decision appends a dated entry, and the tracker keeps the glance plus a link. One page per effort, not per ticket, so the story of a feature reads top to bottom in one place.

The split is an audience seam, and it decides format. Artifacts agents consume — specs, briefs, decision records, glossaries — are markdown in the repo: versioned, diffable, readable by a session with no browser. Artifacts humans read long-form are HTML at the dossier, because HTML beats markdown for human reading. The process itself never cares what evidence is marked up in; that doctrine lives in a writing skill, where format decisions belong.

Evidence, named in advance

Every gate in the machine names its evidence kind before the work starts. A spec's validation gate says what a human will look at to say "yes, it works" — a screenshot, a tried-it note, a preview link — and it is deliberately not a passing test suite. Done's evidence is the canary: proof the deployed change works in production, not proof the deploy pipeline went green.

The evidence stage runs as its own invocation, after implementing, so the judge sits outside the system under test. And repos whose merge changes no production system declare, in their own delivery doctrine, what shipping means there — one repo here ships by a one-line team announcement posted only after its canary, because the message claims the change is live and the claim has to be true first.

Why this is a process concern at all

Principle two says the tracker is the system of record; this page is what makes that record worth reading. A record only humans can navigate defeats the agents; a record only agents can parse defeats the humans. The seam — glance for the board, markdown for the sessions, HTML for the long read — is how one system of record serves both.

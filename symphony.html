The factory running · 02

Symphony, the dispatcher

Symphony is the runner that launches an agent session on a delegated ticket. It is not the brain — everything below the verb lives in the skill tree — and its whole dispatch contract fits in one prompt, published here verbatim.

One text, no branching

The prompt is one unconditional text: it names the issue and its column, and the agent reads the column and acts. One session's worth of work per dispatch, then stop; re-dispatch is the loop.

You are Symphony, dispatched unattended on Linear issue {{ issue.identifier }},
currently in column **{{ issue.state }}**. Look at your column and act
accordingly. One session's worth of work, then stop. Never ask a human.

**Ship** — close out {{ issue.identifier }} ($merge-and-deploy). Ship is the
human's delegation; look for no further approval.

**Backlog** — triage {{ issue.identifier }} ($triage): draft the brief,
perform the route's transition named by the tracker configuration, and
stop. Your delegation is consent for the whole ride — a ticket routed to
Todo keeps it, and implementation follows in a later session.

**Todo / In Progress** — you are working a spec. Read it and its comments,
then look around the workspace: past sessions leave work behind — build on
it, don't restart.

- Every sub-issue Done? Review the diff against the spec, mark the spec PR
  ready for review, move {{ issue.identifier }} to Human Review, and stop.
- Otherwise pick ONE sub-issue: the first in Todo whose blockers are all
  Done. Move it to In Progress, then $implement it on the spec's shared
  branch `spec/{{ issue.identifier }}` and draft PR (create both if
  missing). Run the repo's feedback loops; never commit red. Then run
  $evidence on what you built — the proof comment lands on the sub-issue —
  and move it to Done. Stop.
- Nothing pickable but open work remains? Comment a diagnosis on
  {{ issue.identifier }} and move it to Blocked.
- No sub-issues? {{ issue.identifier }} is its own spec: implement it, run
  $evidence, open its own PR, and move it to Human Review.

**Any other column** — you have no verb here. Comment a diagnosis on
{{ issue.identifier }} and stop.

What each line is doing

ColumnThe verbWhy
ShipClose out — merge, deploy, verifyShip is the human's delegation. The agent looks for no further approval, because the approval already happened when a person moved the card.
BacklogTriage — draft the brief, route the ticketDelegating in Backlog is consent for the whole ride: a clean brief exits to Todo and implementation follows; blanks park the ticket in Needs Decision or Needs Grilling, outside every active state (ADR-0010).
Todo / In ProgressWork one sub-issue of the spec, then evidence it, then stopOne bite per session keeps every session in the smart zone; re-dispatch, not a bigger context, is the loop.
Anything elseDiagnose and stopAn unknown column fails loud and safe. No verb is ever improvised from state the prompt does not name.

Note what is absent: the prompt never plans and never asks. Triage runs here too now — one runner for every session, so failures retry and surface like any other run — but the prompt owns only the choreography: the $triage, $implement, $evidence, and $merge-and-deploy sigils hand off to the skill tree, because the choreography is the one fact that varies with this runner and no other. What Slack gets each morning is a read-only report, not a runner.

The principle underneath: the prompt names only states it has a verb for, and machinery is added against observed failures, never speculative ones. A board state no human touches is a state the process cannot explain.
